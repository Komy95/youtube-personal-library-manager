# Contributing

Read [Development](docs/DEVELOPMENT.md) and [agent rules](AGENTS.md) before changes.
Use synthetic data in examples/tests; keep credentials and account records out
of commits, issue reports and delegated work. Review staged paths and diffs.

Describe the problem and expected behavior in an issue or pull request. Keep
patches focused, document user-visible changes, and include relevant verification.
Run offline tests with the supported Python version; do not use real YouTube
writes as routine CI. New dependencies must have compatible terms and retained
notices. Contributions are supplied under the repository's [MIT license](LICENSE).

Update the project roadmap after each work package with verified results and
remaining limits. Never weaken account binding, credential path protections,
plan approval, preflight, transactional snapshots or journal/retry safeguards.

For setup questions, start with [Setup](docs/SETUP.md) and
[Troubleshooting](docs/TROUBLESHOOTING.md). General support is best effort through
repository issues; redact account information. Report vulnerabilities using
[SECURITY.md](SECURITY.md), not a public issue containing sensitive details.
